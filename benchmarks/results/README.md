# Benchmark results

Committed results live here. Every file is machine-generated by
`zyko bench --json-out benchmarks/results/<name>.json` and records:
zyko version, seed (42), suite hash, per-task verdicts and per-candidate
aggregates — fully reproducible from the recorded inputs.

`_schema.example.json` documents the format without inventing any numbers:
the ledger that the router consumes starts neutral (0.5 everywhere) and is
populated only by real benchmark runs against configured providers.

## The compare ledger (v0.22.0+)

`baseline_2026-11-11.json` is a *provenance envelope* around two real
user-command receipts, generated by `scripts/make_bench_baseline.py` on a real
target (`psf/requests — src/requests/models.py`):

- `compare` — `zyko compare <target>`: classification probes 12/12, byte
  determinism, receipt rotation. The receipt payload is the untouched
  byte-contract `to_dict()` of `CompareReport`.
- `gauntlet_stress` — `zyko gauntlet --per-intent 8 --repeats 2
  --review-sample 6`: repeated matrix determinism + self-review floor
  (min score ≥ 70). Same byte-contract payload.

Reproduce it on your machine and compare the inner receipts byte-by-byte:

```bash
git clone --depth 1 https://github.com/psf/requests.git /tmp/requests-test
python scripts/make_bench_baseline.py /tmp/requests-test/src/requests/models.py /tmp/baseline.json
```

`tests/test_bench_baseline_artifact.py` guards the envelope: version sync with
the installed package, a valid sha256 target fingerprint, green receipts with
honest contracts — and it *re-derives* `zyko compare` live on a committed real
file, so the ledger cannot rot into a stale JSON relic.
